# Pair05 朝左看队友的本机复查

保留现有跟球外参作为下次对照的基准。F12、F24 的几何先验已经对向队友和球，再加左转会改变这份已有构图，且让 F24 原本部分可见的标志盘出画。下一次优先测试生成时如何保留前景。Pair01 展示用[首版成片](../four-egox-outputs-008/verified/pair01_s0288_ego.mp4)。本轮没有开卡，没有调用模型生成视频，也没有使用 Nano。

## 冻结机位与有符号左转

用相同的头部中心、EXO、同帧 ViPE 深度、已有的球和队友标注、佩戴者上身排除、遮挡深度检查与 Aria 镜头投影。本机测试地面上方向为转轴，正值为佩戴者左转，角度为 −15°、−10°、−5°、0°、+5°、+10°、+15° 和 +20°。零度逐物体重现已有像素计数和坐标。下表是 448×448 有效圆内物体已观测像素的横坐标中位数，画面中线为 x=224。

| 帧 | 现有镜头队友 / 球 | 左转 5° 队友 / 球 | 左转 10° 队友 / 球 | 左转 5° 的标志盘变化 |
|---|---|---|---|---|
| F12 | 238 / 231 | 261 / 253 | 284 / 275 | 仍可见一个 |
| F24 | 219 / 228.5 | 242 / 250 | 265 / 272.5 | 原本部分可见的盘由 20 个观测像素到 0，另一个仍可见 |

这是从已经对准前景的几何机位继续转头。用户要的是从成片错拍的围网方向转向左侧队友。相机转左时，原来在画面中的固定景物往右移动。本机正负方向对照符合这个关系。这里测的是两帧真实 EXO 深度的单帧重投影，覆盖率不等同于正式时序先验，也不能从生成围网反推一个真实的偏航误差。

零度另外覆盖了 F00、F04 到 F48 的 13 个 GGA 时间槽。13/13 都有通过遮挡检查的队友和球像素，球横坐标中位数为 228–243，队友为 152–246。队友在 F44 和 F48 逐渐滑向画面左侧，仍有可见像素。除 F12、F24 之外未验证标志盘。这组检查只表明几何中有可用观测。

## 已执行的路由与仍可带入背景的位置

- 对照 004 实际执行的六项文件哈希、路由表、GPU 预检和 4,000 次调用日志。同一批 F12／F24 的 51 个目标块在各层和去噪步重复应用，共占 10,192 个目标块的 0.50%。这两帧单看分别是 26／784 和 25／784。其余 11 个时间槽没有这条专项限制。295 条配对边通过，源块仍遵守 16 点上限。
- 受限分支保留全部 10,192 个 EGO 键，同时只允许 1–16 个匹配的 EXO 键。用实际路由和 CPU PyTorch，在各键的学习得分相等的人工条件下，匹配 EXO 所占权重平均 0.218%，范围 0.039%–0.624%。只保留匹配键的对照实测为 100%。真实 Q/K 分数、值向量和各层残差都没有在该 GPU 运行中采集。
- 全幅 EXO 还进入 VAE 和首帧图像条件，后者经交叉注意力进入去噪。允许的 EXO 块也可能带有邻域内容。几何先验是模型的条件输入，画面中的队友和球并未逐像素固定。F12、F24 正式先验的上半有效圆，按 RGB 最大值不超过 8 测得近黑比例为 96.7%、98.2%。稀疏先验给模型留下较大的补全空间。
- 旧 Aria 成片与 004 成片均按 49 个同一源帧索引解码。F12、F24 围网区域的灰度梯度相关分别为 0.71、0.82，49 帧中位数 0.72。结合画面，两次都保留了围网构图，前景目标仍缺失。两次元数据、正式先验和请求种子一致，GPU 驱动不同，004 同时替换了 171 个源块的几何采样，还加了注意力覆盖。这组回看无法归因到单一代码路径。

## 下一次开卡验证的一项变量

固定现有外参、先验、路由表、权重、文本、步数和种子。需要做因果对照时，两组置于同一机器与环境，复用或核对 VAE 条件随机状态。对照组保持 004 路由；候选组只调整已有目标分支上匹配 EXO 键的相对权重，并保留其余键和掩码。在 F12、F24 的球、队友和标志盘分支，抽样记录前、中、后去噪段的组权重和每组值向量输出的量级，避免只统计调用次数。用 25% 作为一个预设的诊断下限，在人工 Q/K 的 CPU 对照中，52 个低权重分支达到该下限，原已达标的一支保持原权重。25% 是诊断设置，尚未验证它对成片有利。

两帧只有都能辨认正前方白鞋队友、队友脚边单球和对应标志盘才通过，F24 要保住可部分看见的第二盘。围网持续主导、人物或球重复、目标跳动均记录。若真实组权重确实上升而目标仍未回来，保留这次反证，下一阶段单独检查全幅图像条件或几何先验的有效约束。两帧验证通过后，再考虑将匹配扩至相邻时间槽并检查连续性。

## Astra API 复核

通过官方 Responses API 调用 `gpt-6.2-astra / max`，只提交脱敏技术文本。第一轮耗尽 16,000 个输出 token。第二轮缩小到单一干预选择，完成复核，实耗 171 个输入 token、1,509 个输出 token。Astra 建议固定机位与整图条件，只调整 51 个现有查询块的匹配权重，逐分支比较 GPU 干预前后的实际权重。若权重达标而两张关键帧仍以围网居中，局部增权对这次纠偏不足。[实际用量](astra-usage.json)
